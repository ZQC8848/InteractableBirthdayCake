# `.ai/` — 项目共享知识库

写给两类读者：**接手这个项目的下一个人**，以及**帮他的 AI**。

它存在的唯一理由：这个项目里有一些花了时间才搞清楚的东西，代码和 git 历史都不会告诉你。

## 这里有什么

| 路径 | 内容 | 生命周期 |
|---|---|---|
| [architecture.md](architecture.md) | 端到端数据流：一个体素从生成到爆炸经过了哪些步骤 | 跟着架构走 |
| `debug/`（尚未创建） | 事故记录，**按症状索引** | 一次性但要能被找到；目前还没发生过值得记录的事故 |
| [decisions/](decisions/) | 已做的选择、被否决的方案输在哪、什么情况下会推翻 | 可逆——原地编辑，不新开文件 |
| [memory/](memory/) | 共享 AI 记忆，一个事实一个文件 | 长期 |
| [handoff.md](handoff.md) | 进展、进行中的工作、下一步 | **按设计过期** |

仓库里其他地方，但属于同一套体系：

- `CLAUDE.md` — 入口文件，写不明显的平台/SDK 约束
- 本项目暂时没有独立的决策文档，所以决策都放在 `decisions/` 里，一个决策一个文件

## 一条新信息该写到哪

下面所有条件都要满足才算数。

| 你观察到的 | 写到 | 判断标准 |
|---|---|---|
| 不明显的平台/SDK 行为 | `CLAUDE.md` 的约束部分 | 一年后依然成立，**并且**看文档也猜不到 |
| 做了一个选择，否决了别的方案 | `decisions/` | 你能写出"为什么不选另一个" |
| 一个 bug 的症状和根因离得很远 | `.ai/debug/` | 下次会**按症状**去搜它 |
| 进展、进行中的工作、下一步 | `.ai/handoff.md` | 它注定会过期 |
| 某个人喜欢怎么被沟通 | **本地记忆，不进仓库** | 这是关于人的，不是关于项目的 |

**不要写**：代码结构、已经修好的 bug、git 历史里已经写清楚的东西。这些东西会立刻过时，而原始来源永远更准确。

## 晋升本地记忆的判断标准

**换一个人做这个项目，这条还成立吗？** 成立就该晋升进来。

## 一个记忆文件只放一个事实

这样两个人的修改才不会冲突。塞进一个大文件里，冲突是必然的。

## 对抗文档腐烂

代码写错了会编译失败；文档写错了什么都不会发生，所以它会一直烂在那里，而 AI 写文档的速度比人验证的速度快得多。

1. 写**可以被核实的东西**，不要只写结论
2. 任何别人可能需要确认的说法，标注 `file:line` 或一条命令
3. debug 记录要有**测量数据**，不要只有结论
4. 给每份文档打上日期，让"过时"这件事可见，而不是被默认忽略
